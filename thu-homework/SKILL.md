# 清华网络学堂作业助手

面向 `learn.tsinghua.edu.cn`，完成「本地资料 → 检查作业 → 用户选择 → 制作交付物 → 提交核验」。按用户这次的范围执行：只查作业就只检查；已指定作业则直接核对；要求完成并提交时，选择生效后持续做到拿到回执。

## 1. 本地资料与登录

选定作业工作目录，技能源码目录只存可公开文件。默认个人资料路径为 **作业工作目录下的 `.thu-homework.private/profile.env`**；若用户指定已有凭证文件，使用其路径。以下命令中的技能路径、资料路径均替换为实际绝对路径，依赖与启动方式见 [平台操作](references/learn-platform.md#运行环境)。

```bash
python /absolute/path/thu-homework/scripts/credentials.py init --env /absolute/path/workspace/.thu-homework.private/profile.env
python /absolute/path/thu-homework/scripts/credentials.py check --env /absolute/path/workspace/.thu-homework.private/profile.env
```

`init` 创建空模板或补齐缺失的键，不覆盖已有值；`check` 只返回缺失字段和文件路径。必填 `name`（姓名）、`number`（学号）、`password`（密码），可选 `totp`。检查不通过时，给出**可点击的实际文件路径和缺失字段名**，引导用户在该文件填写后回复“已填写”；保留这一待办并暂停依赖登录的工作，收到回复后重新检查。不要让用户在聊天中发送密码或 TOTP 密钥，也不要自己猜姓名或学号。

不要直接读取输出整个凭证文件、`source` 它或把值放进命令行。凭证不得进入技能目录、Nix store、作业附件或 Git；脚本会拒绝技能目录内的资料路径。姓名和学号仅在作业要求署名或命名时使用。按[平台操作中的登录说明](references/learn-platform.md#登录)使用临时浏览器；二次验证、验证码需要用户介入时，只请求当前缺少的步骤。

## 2. 检查并让用户选择

登录后核对当前学期，遍历实际加载的课程、作业状态标签和分页，读取课程全名、课程号、教师、作业标题、截止时间、提交状态及能否补交。除用户指定范围外，默认检查当前学期全部课程。具体导航见[查找作业](references/learn-platform.md#查找作业)。

- 将尚未提交且可提交的作业列为候选；截止时间按 `Asia/Shanghai`（北京时间）显示，补交项明确标注。
- 已提交、已批改、过期关闭的作业单独说明，不默认重做或覆盖。加载失败的课程标为“未能检查”，不能据此报告“没有作业”。
- 没有候选时简洁报告检查范围、结果和未检查项，不抛出空问题。
- 有候选且用户尚未指定时，先给一个编号表：`编号 | 课程 / 作业 | 截止时间（北京时间） | 状态`，再**实际调用提问工具**让用户选择；不要只说“我会询问”，不要自行全选。

优先使用环境提供的 `question` 工具，有多选功能就启用；否则使用 `request_user_input_async`。工具不支持多选时，用一个文本问题接受编号列表。仅在当前模式允许时使用 `request_user_input`；没有提问工具才在最终回复中提问并等待。

建议问题：**“要完成并提交哪些作业？回复编号（如 1,3）、‘全部可提交’或‘暂不处理’。”** 若用户只授权检查或制作，把问题里的动作换成相应范围。选项列出实际作业；回答“全部”只指这次展示的可提交候选，后续新增作业另行询问。等待明确答案；超时、无答案、预选选项均不算选择。只有一个候选也要让用户选，除非已明确指定它。

用户对“完成并提交哪些”的选择即授权这些作业的完成和提交，不在提交前机械地再问一次。对“只完成”“先给我看”“不要提交”等限制严格照办。匹配不清或用户选择了表外作业时，先核对准确课程和标题。

## 3. 完成所选作业

逐项读完线上要求和教师附件，再检查对应本地作业目录。提炼需要回答的问题、交付文件、格式/篇幅/命名、实验或截图证据、提交截止时间；以实际题目为依据，不套固定报告结构。按截止时间安排，期间无需重复请求继续。

**写作与设计约定：需要写的才写，内容完整、表达简洁、版面优美。**

- 只要求代码、答案、图片或表格，就交这些内容，不额外写报告。只有题目要求报告，或解释确实是答案的一部分时才写。
- 报告围绕必答问题和必要证据组织。没有要求且无助于回答的问题，不加封面、目录、摘要、背景综述、环境介绍、重复题意、工作流水账、泛泛总结或参考文献。
- 简洁不等于省略必答项：要求的推导、解释、结果、分析和篇幅必须满足。能用一句话、一张表或一幅图说明的内容，不重复展开。
- 统一字体、标题层级和间距，保留适当留白；图表清晰可读，代码和公式不溢出，导出后检查实际页面。遵守教师模板优先于个人排版偏好。
- 代码运行必要的样例或测试；实验数据、图表和截图来自实际运行，不能编造。缺少数据、设备或关键题意时，完成独立部分，再就阻塞项提问；不把未完成作业当作成品提交。
- 已有用户成品先检查并复用；不要无故重写。姓名、学号按要求填写，不将内部检查清单、登录步骤或提交回执写入学术报告。

## 4. 提交并核验

只为用户选择且授权提交的作业操作。按[提交和回执](references/learn-platform.md#提交和回执)执行；每项提交前复核课程、作业、截止状态和实际必交文件。打包采用明确文件清单，排除凭证、会话、缓存、`.git`、无关作业和内部回执。

提交前若发现已有提交，先核对附件；内容相同则直接核验，不重复提交。需要替换且用户尚未授权替换时，列明具体作业和新旧文件再询问。已明确要求更新/重交该项时直接执行。

点击最终提交后等待完成，不重复点击。超时或断网先查平台状态；状态仍不清楚就停止该项写入，报告“待核验”，不能盲目重试。一个作业失败不妨碍继续处理其他已获授权且独立的作业。

成功至少需要平台的“本人提交的作业”、提交时间和正确附件；能回读附件时比较字节数及 SHA-256。分别报告“已提交且附件一致”“已提交，附件完整性待核验”“提交状态待核验”或具体失败，不把点击按钮当作成功。

结束时关闭临时浏览器，每项保存一份不含令牌的本地回执。最终只简要列出作业、状态、平台提交时间及交付物/回执链接；不要声称成绩或通过验收。
